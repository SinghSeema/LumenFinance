EMI Reminder Agent: Evals

How we know the Lumen Finance reminder agent is good, and where it is not. Laid out along the assignment brief: the borrower responses it lists, its metrics, latency, real failures and what changed. Every conversation is readable at the bottom.

How the evals run

  • Scenarios: 17 borrower scenarios, each with a persona, a hidden goal and the expected outcome record. 12 dev scenarios were used while building; 5 hold-out scenarios were kept unseen until the baseline run.
  • Simulated borrower: an LLM (, a different model family from the agent) plays the borrower in text. It sees the persona and goal, never the expected outcome. Each scenario runs 5 times, because conversations vary.
  • Same code as the live agent: the eval drives the same Brain, tools and guards as the voice bot; only audio is skipped.
  • Rule-based scoring (evals/score.py) for everything a rule can decide: outcome fields, disclosure before verification (from a log of every loan fact the model saw), escalation, dates, language, and process checks such as "says it is an AI when asked".
  • LLM judge (evals/judge.py, glm5.3-flash) only for tone: politeness, empathy, firmness, clarity and naturalness, 1 to 5. Any guardrail flag must quote the agent's exact words or it is dropped. Trust is low: a spot check of the 9 lowest scores found it punishing correct refusals (not telling a family member the amount; ending the call after "stop calling me"). Not calibrated against hand labels yet.
  • Hand review: every failed conversation was read in full and marked as an agent defect, a code bug, or a test-side error (simulator off script, scorer wrong).

Latency (live voice calls)

Per turn: from the moment voice activity detection says the caller stopped, to the first audio played. The caller also waits the 0.5 s silence before that. Target: median under 1.2 s, p90 under 1.8 s. Each bar counts turns in a 250 ms band; current stack only.
